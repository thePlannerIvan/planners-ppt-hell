# 1. Workbench 作为主交付物与默认工作终点

- **Status**: accepted

我们把持久化 SVG 视觉工作台（`review`）定为 `planners-ppt-hell` 的主交付物与默认收尾终点，且普通页面不设人工批准门；可编辑 PPTX 导出（`export`）仅在用户明确要求导出或从工作台主动触发导出快照时按需执行。

## Considered Options

- **继续以导出 `.pptx` 作为四阶段主线的终态**：模型每次画完页面都会抑制不住冲动直接运行 `export` 交出 `.pptx`，把工作台当成导出前不得不点一下的中间检查站，导致未审阅的错版 `.pptx` 泛滥。
- **工作台即主交付物、导出降级为按需外发分支**：默认主线收束为「接收 → 定方向 → 工作台制作与审阅交付」，工作台本身即幻灯片呈现与协作终端；模型完成后停在打开/刷新工作台交给人看。

## Consequences

- `SKILL.md` 默认主线收束为三步，与 `writing-for-agents` 的步骤边界一致，切断后续导出步骤对当前回合的抢跑拉力。
- `ppt_pipeline.py next` 不再在所有页校验通过后提示模型可以 `export`，而是明确指引打开或刷新 `review` 工作台。
