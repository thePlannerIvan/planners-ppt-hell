# 视频画面路线

## 这条路线在做什么

上游 `video-idea-system` 把**已经批准的逐屏画面契约**交过来，你把它变成**录制前就能用的静态画面**：每屏一张 SVG，屏幕上该出现什么、图上摆哪张真素材、花字打在哪，都照着契约画。

三件事按顺序做完：**接手**（把包立成账本、把视觉身份定下来）→ **逐屏画**（边画边真的看）→ **整套**（并排看一遍，然后交给作者过目）。走完 V3 的完成标准，这条路线就结束了。

## 为什么单独一条路线

它和幻灯片路线**共用同一套画面机制**（画布几何、校验器、渲染、看图、版本绑定），但有三处根本不同：

1. **内容不是在这里判断的。** 契约已经定好每屏的上屏文字与素材——画面上文字来自 `must_show`／`exact_labels`／`sample.captions`，理由与证据只用来理解，不上屏。所以**不做内容取舍**，也不重新编号（`screen_id` 原样成为 `page_key`）。
2. **视觉身份来自风格库，不是模板库。** 风格库是配色与字型 token（`video-craft/visual/themes/`）；模板库那套是从 PPTX 提出来的带锁层品牌模板，锁层里烤着满幅不透明矩形和一条落在字幕区上的页脚线——套到要压在素材上的视频画面上会直接毁掉画面。
3. **出口是 SVG，不是 PPTX**，因为后面还要按实测音频做轻动画。所以交出去的不是几张图，是一个**能被按元素指名的活结构**（见最后一节）。

## 输入及其作用

| 输入 | 在这里用来判断什么 |
|---|---|
| `visual-plan.json`（契约 5.0） | 每屏要画什么、上屏什么字、花字顺序、样张定下的素材关系 |
| `<包>/assets/` | 真素材。**它恰好等于契约引用的那几张**——不是作者的素材库 |
| `video-craft/visual/themes/` 的风格 token | 候选视觉身份 |
| 上游**已经过**的念稿审阅 | 作者已经确认过四件事：放哪张图、两张图是不是对比关系、用什么模型展示、模型上有什么字。**这四件继承，不重判**。这不是包里的文件——记录在上游自己的 `_idea/reviews/script/` |
| 契约旁边那份 `script.md`（**不是内容输入**） | **只用于核对哈希**：口播不作为输入进来，不拿它判断画面内容；核对时机与判据见 `00_pipeline_controller.md` |

## 开局一次问清：风格与画幅

```bash
# 立项目（三个路径都给绝对路径）
python scripts/init_svg_project.py <项目>/<画面目录> \
    --assets <包>/assets --plan <包>/visual-plan.json
```

初始化在边界上把契约翻成内部的 `page_content.json`，并登记图片。然后**一次问清这两件，都不静默默认**：

1. **风格** — 报 2–3 个候选给作者挑，每个带色与字型的预览：
   ```bash
   python scripts/style/theme_tokens.py list          # 库里有什么
   python scripts/style/theme_tokens.py show <theme-id>   # 这一个展开成什么样
   ```
   选定后把该主题的 `:root` token 块内联进每页的 `<style>`，元素的颜色与字体经那份 `<style>` 里的 class 规则取（`.title { fill: var(--text); font-family: var(--font-body); }`，元素写 `class="title"`）。`show` 会把 `var()` 全部展开成实际值，**并报出解析不掉的 token**——那些是主题自己的缺陷，别默默当没有。
   检查画面认这三种取法：元素属性、元素 `style="…"`、class 命中的同页 `<style>` 规则；三处都没有才算缺填色／缺字体。**页里引用了没定义的 token 是硬错误**（会点名哪个元素、哪个 token），所以 token 名从 `show` 的输出里抄，别手打。
   库里没有贴合的，就走自主设计，并在 `design_direction.md` 里写清这套画面的色与字从哪来。
2. **画幅** — 默认 16:9，确认一次。要给人物留窗口时**仍然是这张 16:9**，留窗口是排版选择，不是换画幅。

## V1 接手：把包立成账本，把身份定下来

**主要结果**：项目有了自己的账本（每屏的图与字都在册），且视觉身份**已经定过一次**。

**判断框架**

- 上游已定调的**只继承不判断**：这一屏用哪张图（真实路径）、图与图的关系（并列／对比／因果／时序）、用什么模型展示、模型上必须出现哪些字、花字层的内容与出场顺序、`screen_id`／`beat_id`。
- 在这里定的：网格与栏数、沟槽、边距、纵向步长；层级角色与字号档位；色彩角色与强调色落点；跨页锚点、页码页脚位置；整套节奏。图形的具体几何、留白多少、构件选用。

**写 `_internal/01_content/design_direction.md`。** 它在**这条路线上是必填**（没写 `check` 会拦），内容按 `../domain/style_system.md` 的顺序组织，并写清**四条视频约束**：

| 约束 | 写清什么 |
|---|---|
| **字幕安全区** | 画面底部留出不放内容的一条——剪辑会在这里烧语义字幕 |
| **人物位置** | 满屏画面＋角落人物窗口／全屏人物与画面切换／分开交付；落到画面就是留出（或不留）哪一块 |
| **不透明与透明** | 哪几屏是满屏替换、哪几屏是压在素材上。默认整片一种，例外写在该屏 |
| **强调动画余量** | 元素之间的间距够不够让它们分先后出现——录后按实测音频加轻动画时要用 |

其中**三条要写成机器可读的键**，不只是散文：在 `design_direction.md` 里放一个**带 `composite` 键的 fenced `json` 代码块**。

| 契约键 | 对应哪条约束 | 取值 |
|---|---|---|
| `composite` | 不透明与透明 | `"replace"`（满屏替换）／`"over-person"`（压在人物上） |
| `personWindow` | 人物位置 | 页面坐标矩形 `{"x","y","w","h"}` |
| `captionSafe` | 字幕安全区 | 页面坐标矩形 |

**键名与取值域的唯一来源是 `video-craft` 的 `references/composition-facts-contract.md`**——本 Skill 点名要求这三个键，**不自己造字段名**，也不在这里复述谁填谁读、缺了会怎样（那份契约写）。**强调动画余量**没有对应的键，它是画面自己的间距要求，散文写清即可。

**产物**：`page_content.json`（适配而来）、`design_direction.md`、登记好的图片账本。

**完成标准**

- 机器：每屏要么有上屏文字、要么有登记图片（两者都空是缺陷，不是「暂时没想好」）；`assets/` 里每张图都有归属，**包外的东西一张没进来**。
- 语义：**风格选定并写清它怎么落地**；四条约束四条都写了，其中三条按契约写成 `composite` 键的 json 代码块；`design_direction.md` 里的秩序足以让任意两页并排像一套。
- 不由校验器证明：风格选得对不对、这套秩序配不配这段内容。

**不要做**：不重新编号；不改写上游的上屏文字；不判断内容对不对；不套模板库。

## V2 逐屏画：边画边真的看

**主要结果**：每一屏都被**看过**，而且看完的结论是有内容的。

制作与逐页自检的完整任务在 `04_svg_stage.md`（两条路线共用）。这条路线额外三条：

1. **给可能被强调的元素铸稳定 `id`。** 这是交给动画层的唯一接口。**id 在整个片子里唯一**：把 `page_key` 放进名字里（`beat-04-caption-1`、`beat-04-model-stage`），不要每屏都叫 `caption-1`。这些页面会被**内联进同一个 DOM**（一屏一层 `<section class="clip">`），重复的 `id` 会让「按 id 指名」只命中第一屏——想强调第 4 屏的元素，实际打到第 1 屏。
   名字还要能读出它在画面里是什么（`caption`、`label-tony-alva`、`model-stage` 这类词 + 屏号前缀）。同一页里 id 重复是非法 HTML，检查画面会拦下（`DUPLICATE_ELEMENT_ID`）；跨页碰撞由导入器在导入前报告。
   **用 id，不用 DOM 序号。** 画面重渲时只要多出一个 `<text>`，按序号指的元素就会**静默绑到别的东西上**——该强调的地方强调到错处，而且不报错。
2. **看图必须由能看图的模型执行。** 看的是**每页 PNG 大图**，不是联系表里的缩略格。当前模型读不了图就把它派给能读图的模型。
3. **`inspect` 记录要诚实。** 除了原有的三个字段，还要**指出当前 PNG 上的一处具体位置**，并**明确选一个**：`--clean`（看过，无缺陷）或 `--must-fix`（看过，有缺陷且已记录）。填 `ok`／`👀` 不通过。

**判断框架**：看渲染图，不看代码。问这一屏的模型有没有承载 `must_express`；花字有没有绑定它强调的那一句；文字有没有被截断或压住。

**完成标准**

- 机器：每屏 `check` 无 error（含**文字出画布**）；每屏都有一条针对**当前**版本 PNG 的 `inspect` 记录；可能被强调的元素都有 id。
- 语义：`inspect` 记录里说得出这一屏**第一眼落在哪**、有什么缺陷。

## V3 整套：并排看一遍，然后交给作者

**主要结果**：整套像一套，四条约束真的落地了，**并且作者看过**。

**做什么**

1. 看整套 contact sheet：构图是不是重复、明暗与密度有没有节奏、跨页重复元素是不是落在同一组坐标上。
2. 四条约束逐条对照画面。
3. **跑整套审阅**：`python scripts/orchestrate/ppt_pipeline.py <项目> review`，让作者在页面上逐页给意见。
   幻灯片路线上审阅是可选的；**这条路上它是门**——作者要对着这些画面讲口播，图、模型、花字一旦录进去就改不动，改一屏就是重录那一段。
4. 作者的意见逐项落回本阶段修改，然后用 `resolve` 记录。

**完成标准**

- 机器：全部页面 `check` 无 error；审阅有记录；作者提交的意见全部 `resolve` 或明确挂起。
- 语义：模型给出四条约束的逐条对照；作者明确说过「可以录了」。
- 不由校验器证明：风格落得对不对、这一套画面配不配这段口播。**这一条只有作者能答。**

## 交出什么：给动画层的交接

这条路线**不导出 PPT**。交出的是 `_internal/02_svg_source/<page_key>.svg` 全部页面。

### 为什么是 SVG

后面要按**实测音频**做轻动画——讲到哪强调哪。动画要能**按元素**指名（这块先出现、那条线划开、这个数字跳出来），所以页面必须是**活的、可指名的结构**，不是一张栅格图。实测过 44 张真实页面：文字是真 `<text>` 不是路径（逐字动画可行）、没有 clipPath／mask／transform 被拍平、画布 44/44 都是 `viewBox="0 0 1920 1080"`（**页面坐标 = 视频像素**，挂时间轴不用换算）。

### 页面这一侧的责任

- **可能被强调的元素带稳定 `id`，且 id 在全片唯一**（把 `page_key` 放进名字里；见 V2 第 1 条）。
- **页面里不加动画。** 动画在录后、在页面之外加。
- **图片 href 保持页面自己的相对形式**，那是给幻灯片出口用的；**导入时的前缀改写归导入器**，不要为了让导入器好写而改页面的 href。
- 页面可以用 `<style>`、动画与视觉效果——它的出口是 PNG，承载得住（见 `../domain/svg_rules.md`）。

### 剪辑那一侧的责任（写在这里，好让两边对得上）

- 把页面**逐字内联**进 composition，**只改写图片 href 前缀**，页面标记一字不动；生成器要能证明只回写那一处 href 就能还原原文一字不差。
- 动画**只加在外层**（包裹层上的 clipPath／stroke-dasharray／transform）。
- **按 `id` 指名元素**，不用 DOM 序号。
- 从 `design_direction.md` 读合成方式、人物窗口位置与字幕安全区。

## 不要做什么

- **不导出 PPTX。** 这条路的产物是页面源，没有下游消费者需要 PPT。
- **不为过闸去删源素材。** `--assets` 报「文件夹里有图没被引用」时，正确的解法是指向交付包 `<包>/assets/`；作者的素材库不是交付包，删它就是这个工作区刚丢掉 6.9 GB 的那类操作。
- **不判断内容。** 声明是上游给的，照它画；发现声明本身有问题，反馈回上游，不自行改写。
- **不给页面加动画。** 那要等实测音频。
- **不套模板库。** 理由见上面「为什么单独一条路线」第 2 条。
