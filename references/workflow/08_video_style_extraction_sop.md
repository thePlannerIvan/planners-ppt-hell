# 视频视觉风格与预埋动效模板提取 SOP（Reference Board → Dual-Skill Template）

当用户给出一批参考画板（如 Pinterest 画板链接、一组喜欢的视频/GIF/排版截图），希望将它们提炼成一套可在 `planners-ppt-hell`（视频静态画面生成）与 `video-craft`（录音后动效合成）之间无缝交接的**视频风格模板**时，按本文件执行。

本流程沉淀自 `editorial-archive`（34 个 Pinterest 样本：25 张静态/轮播图 + 9 个视频/GIF → 四域×独奏/群像系统 + 8 种复合子元素预埋动效）的完整实战经验。

---

## 为什么不能只提一张色卡？

视频画面与传统 PPT 模板有两处本质差异：

1. **同一支视频里有多种功能画面，但必须像同一套设计**：口播视频一会儿要立金句（文字凸显）、一会儿要画逻辑图（模型构建）、一会儿要摆证据截图（图片为主/图文混排）。如果把参考图拆成几个互不相干的主题，整支视频要么单调重复，要么换页像换了频道。
2. **静态画面是下游动画的预制件**：`planners-ppt-hell` 与 `video-craft` 是前后脚关系。如果静态 SVG 在生成时没有按动作拆好子元素层级（`.anim-*`）与路径（`pathLength="1"`），下游做动画时就只能对整个 `<g>` 做平庸的「透明度+上浮（`opacity + translateY`）」，或者被迫重画 SVG。

因此，提取一套视频风格模板，交付的不是一份 `tokens.css`，而是**「四域×独奏/群像视觉规范 + 多模态参考图包 + 复合子元素动效预埋契约 + 真项目 `/prototype` 验证」**。

## 完整六步提取流程

### Step 1：全量一手采集与动态关键帧抽帧（Source Harvesting）

不要只看网页缩略图或只抓几张图。先调用 `/research` 把画板里的所有样本原件落盘：

1. **分类落盘**：
   - 静态单图：保存最高分辨率原图（`orig` / `736x`）。
   - 轮播多图（Carousel）：把轮播里的每一页（`slot-01 .. slot-N`）全部抓下来——轮播恰恰展示了同一个设计师如何在多页之间保持视觉脊柱一致。
   - 动态样本（MP4 / GIF）：下载原视频/GIF，并用 `ffmpeg` 抽取 **6 张关键帧序列**（`0%, 18%, 36%, 54%, 72%, 90%`）存入 `frames/`。
2. **登记 `manifest.json`**：记录每个样本的编号、媒体类型、尺寸、时长、原始链接与本地路径。

### Step 2：双路子代理并行拆解（静态视觉簇 × 动态子元素时序）

派两个研究子代理并行读图（利用模型的多模态看图能力逐张 `view_file`）：

| 子代理 | 看什么 | 必须回答的问题 |
|---|---|---|
| **静态视觉分析师** | 全部静态图 + 轮播全套页面 | ① 背景材质与色板（hex 估值、纸纹/网格/暗底）；② 字体混排与字重反差（衬线/无衬线/等宽如何分工、最大最小字号比）；③ 几何骨架与 SVG 构件（分割线、编号胶囊、节点框、相纸框、印章、角标怎么画）；④ 什么破坏这套风格（失败边界）。 |
| **动态与 SVG 结构逆向师** | 全部视频/GIF + 6 帧序列 | ① 哪一层是**全程不动的锚点（Anchor）**？② 哪些元素在动，每个动作的**子元素先后顺序**是什么（如先刷底色条→再出字→最后盖章）？③ 要想让 `video-craft` 免重画直接驱动这些动作，`planners-ppt-hell` 画静态 SVG 时必须怎么分组（`<g>`）、加什么属性（`pathLength="1"`、`data-anim`）？ |

### Step 3：收敛为「全局脊柱 + 四大功能域 × 独奏/群像呼吸阀」

拿到两份报告后，不要直接照搬子代理分的 A/B/C/D 簇，而是按视频叙事职责做三步收敛（**建议在此步用简洁表格向用户确认一次合并逻辑**）：

1. **提炼全局统一脊柱（Global Spine）**：
   - 锁定 1 套主底色（如暖生纸 `#F2EFE9`）、1 套主墨色（`#181715`）、**唯一 1 个低饱和度主强调色**（如编辑砖红 `#C8553D`）+ 1 个高光辅助色（如氧化黄 `#E9C46A`）。
   - 锁定 4 个字体角色（`--font-display-cn`、`--font-display-en`、`--font-body`、`--font-mono`）与全片统一的页眉轨、人物留白窗、字幕安全区。
2. **按四大功能域归并版式（4 Functional Domains）**：
   把散乱的参考图归入视频每一屏必选其一的四个领域：
   - **域 1：文字凸显 (`text-focus`)** —— 立金句、列核心痛点、章节重音切换
   - **域 2：模型构建 (`model-build`)** —— 画流程闭环、正交分支树、机制公式
   - **域 3：图文混排 (`editorial-mix`)** —— 左结论/指令卡 + 右真实证据图 + 手绘圈注咬合
   - **域 4：图片为主 (`image-archive`)** —— 展示一手历史照片、长文档截图、本地文件铁证
3. **强制加入 `Solo（独奏极简）` vs `Multi（群像展开）` 密度呼吸阀**：
   - **这是防止 AI 做页面「越做越满、千篇一律」的关键一步。**
   - 每个功能域都必须同时定义 **Multi（群像模式：2~4 个卡片/节点/多图叠放）** 与 **Solo（独奏模式：全屏只强调 1 张大图、1 个巨字金句或 1 个核心公式，留白 ≥ 60%，去掉侧边栏与多余装饰）**。
   - 规定全片 `Solo` 屏占比不得低于 `30%`。

### Step 4：定义「复合子元素分阶段动效」预埋契约

**绝对禁止**只定一套「整组 `<g>` 淡入上浮」的简单动效。把动态样本里的精致动作拆解为 **3~4 个子元素的微时序差（80~150ms 错峰）**，固化为 `data-anim` 配方：

- 每个动作原语（如 `bar-wipe`、`pop-card`、`z-stack-drop`、`stamp-in`、`slot-expand`、`draw-stroke`、`paper-unroll`、`highlight-sweep`）必须明确规定：
  1. **SVG 内部必填的语义子选择器**（如 `.anim-bar`、`.anim-mask`、`.anim-title`、`.anim-sub` 或 `.anim-shadow`、`.anim-frame`、`.anim-photo`、`.anim-tape`）；
  2. **子元素的先后触发时间表与缓动曲线**（如相纸先带弹跳落桌 → 阴影同步收紧 → 照片轻微缩放显影 → 胶带从上方贴合 → 底部打字机图注浮现）；
  3. **静态与终态完全一致原则**：不跑动画直接渲成 PNG 时，就是完美的最终静态构图。

### Step 5：用真实项目跑 `/prototype` 闭环压测（必做，不许跳过）

规范写完后，**绝不能直接发版**。必须挑一个已经做过的真实视频项目（有真实的 `visual-plan.json`、`script.md`、真图片素材和旧版 SVG 反例），构建一个可离线双击打开的交互原型（`/prototype`）：

1. **覆盖全部四域与 Solo/Multi 模式**：重画该项目的 6~7 屏 SVG，确保四个功能域和 `Solo` 单图/单字独奏屏全部上场。
2. **同屏新旧对比 + 步进播放**：原型页支持一键切换「新版预埋动效 SVG vs 旧版静态 SVG 反例」，支持 `Step 0 (Anchor) → Step 1 → Step 2...` 自动按口播句子步进播放。
3. **渲染成 PNG 逐屏看图自审**：用無头浏览器截取每屏高清 PNG 和 7 屏联系表，自己先用 `view_file` 检查这四件事：
   - 重音屏的颜色是不是太刺眼？（刺眼就立刻降饱和度、改用深炭墨底+小面积点缀）
   - 有没有每一页都塞得太满？（太满就拆出 `Solo` 独奏屏，砍掉多余标签和印章）
   - 动画播起来是不是只有整块浮现？（是就补齐 `.anim-*` 子元素分阶段时序）
   - 有没有文字出框、重叠、或 `<g>` 动画后飞到左上角 `(0,0)`？

### Step 6：双端 Skill 落盘、多模态参考图入库与同步发布

原型经用户确认后，按单一真源原则落入两个 Skill 并运行测试：

1. **`video-craft` 侧**：
   - `visual/themes/<theme-id>/theme.json` + `tokens.css`
   - 若新增或更新了动效原语，同步更新 `references/svg-animation-contract.md` 与 `visual/assets/svg-anim-engine.js`
   - 更新 `references/themes.md` 内置主题表
   - 跑 `python3 visual/scripts/check_themes.py` 与 `tests/` 单元测试
2. **`planners-ppt-hell` 侧**：
   - 把精选的 **8~12 张代表性原图 + 实测联系表** 拷入 `assets/video_style_references/<theme-id>/`（保留多模态视觉锚点，体积控制在 3~5MB 内）
   - 新建 `references/domain/video_style_<theme_id>.md`，写明全局脊柱、6 条反杂乱护栏、四域×Solo/Multi 矩阵、带 `.anim-*` 的 SVG 代码模板，并在开头链向随包多模态参考图
   - 在 `references/workflow/03_video_route.md` 与 `references/architecture.md` 挂好入口
   - 跑 `scripts/test/` 单元测试（其中 `test_theme_tokens.py` 会自动验证新主题在两边完美解析）
3. **全运行时发布**：
   - 先跑 `python3 02-skills-library/publish_skills.py --target all --dry-run`，确认无误后跑 `--target all`。

## 6 条实测必踩技术坑（Empirical Gotchas）

以后提取新模板或写预埋动效 SVG 时，逐条对照以下 6 条血泪教训：

| # | 现象（踩过的坑） | 根因 | 强制解法 |
|---|---|---|---|
| 1 | **一播动画，元素飞到画布左上角 `(0,0)`** | 在 `<g data-step="1">` 上写了 `transform="translate(680, 240)"`，而 WAAPI / GSAP 执行动画时重写了 `element.style.transform = "translateY(0)"`，直接覆盖掉了 SVG 的 `transform` 属性。 | **`<g data-step>` 严禁挂定位 `transform`！** 所有子元素的 `x / y / d` 直接用 `1920×1080` 画布绝对坐标；拍立得的旋转角写在内部子 `<g class="card-tilt" transform="rotate(...)">` 上。 |
| 2 | **卡片/印章缩放或旋转时，绕着左上角 `(0,0)` 大甩尾** | SVG 元素的默认 `transform-origin` 是整个 `<svg>` 的 `(0,0)` 原点，而不是元素自身中心。 | 在 CSS / 动效引擎里统一对 `[data-step]` 及其子元素设置 `transform-box: fill-box; transform-origin: center;`（GSAP 中配 `transformOrigin: "50% 50%"`）。 |
| 3 | **重音屏用高饱和朱红色铺满全屏，看一眼就刺眼廉价** | 把印刷海报里的小面积高光色直接当成了 1920×1080 发光屏幕的满幅背景色。 | **重音反转屏（Spotlight）一律用深炭墨（`#181715`）作主底**；主强调色（如 `#C8553D`）调为低饱和度氧化砖红，且面积严格 `≤ 12%`。 |
| 4 | **模型每页都画满边框、胶带、印章和侧边栏，单图单字反而不会排** | 规范只给了「有什么构件」，没给「什么时候做减法」，模型默认把所有构件堆在一页上邀功。 | 规范必须显式定义 **`Solo（独奏极简）` vs `Multi（群像展开）`** 两档模式，并硬性规定 `Solo` 屏留白 `≥ 60%`、严禁加侧栏与多余印章。 |
| 5 | **动效只有生硬的整块浮现，没有参考视频里的精致感** | 只在 `<g data-step>` 上加了 `data-anim`，但 `<g>` 内部是一陀扁平标签，引擎只能对父级 `<g>` 做整体 `opacity` 过渡。 | 必须在 `<g data-step>` 内部标出 `.anim-bar` / `.anim-mask` / `.anim-bg` / `.anim-border` / `.anim-title` / `.anim-photo` 等**子元素类名**，由引擎做 3~4 步错峰微时序。 |
| 6 | **`check_themes.py` 报错退出** | 在 `video-craft/visual/themes/` 下放了非主题目录，或者 `--text-mute` 对比度低于 `4.5:1`，或者残留了 `--dur-*` / `--ease-*`。 | `visual/themes/` 下只能放合法的主题目录；浅色纸底上 `--text-mute` 至少深于 `#6E6A63`（对比度 `≈ 4.65:1`）；提交前必跑 `check_themes.py`。 |
