# 制作与视觉自检

结果：实际可读、跨页一致的 SVG 页面。内容处理、布局、裁剪和 SVG 由当前主 Agent 一起完成，不另做线框审阅。

开始本阶段时按顺序读：`../domain/style_system.md` 的**设计总规则**（先定读法与秩序）、`../domain/layout_taxonomy.md` 的**信息组织判断**、`../domain/svg_rules.md` 的**通用技术规则与纵向构造**。**走幻灯片出口的再加读 `../domain/svg_to_ppt_rules.md`。** 材料与相邻页始终可回看。

## 开局：视觉身份与画幅

**视觉身份从哪来，取决于走哪条路：**

| 路线 | 视觉身份 |
|---|---|
| 幻灯片 | 模板库／视觉参考／自主设计（`01_template_intake.md` 的 A／B／C） |
| 视频画面 | 风格库（`video-craft/visual/themes/`）／自主设计（`03_video_route.md`） |

**模板库是「用」不是「建」。** 库里有贴合的，就用它开工：

```bash
python scripts/template/template_library.py list
```

库里没有贴合的，就走自主设计或视觉参考（`01_template_intake.md` 的 A／C 路线）。**做画面这一路永远不需要经过模板提取**——从用户已有 PPTX 里提出一整套可复用模板是**另一件独立的、很重的活**（同文件 D 路线，八步），只在用户要真实复用自己品牌资产时才走。

**视频画面路线不套模板库。** 模板库的条目带锁层，锁层里烤着满幅不透明矩形和一条落在字幕区上的页脚线；视频画面要么满屏替换、要么压在素材上，锁一层不透明满幅矩形两个都做不了。这条路上挑的是**风格库**。

**画幅归一 16:9。** 默认 16:9（1920×1080），开局与用户确认一次，之后同一套保持画布一致。
**视频不是另一个画幅**：需要给人物留窗口时，**仍然是这张 16:9**，只是在版面上留出一块不承载内容的区域——这是排版选择，不是换画幅。
画幅的机器取值只有一个 owner：`scripts/canvas_frame.py`（归本阶段）。其他模块从这里取，不再各自写数字。

## 先定整套秩序，再画单页

在 `_internal/01_content/design_direction.md` 里先写清这套页面共同遵循的东西，再动手：

- **网格**：栏数、沟槽、边距、纵向步长。
- **层级角色**：哪几档、每档固定承担什么（页标题／区块标题／正文／标签）。
- **色彩角色**：强调色只落在哪里，语义色对应什么。
- **重复出现的元数据**：页眉栏目名、页码、页脚，以及它们的位置。
- **节奏**：这套页面在明暗、密度、尺度上怎么起伏。

**视频画面路线上这份文件是必填**（缺了 `check` 会拦下），而且要在里面写清四条视频约束——**字幕安全区／人物位置／不透明与透明／强调动画余量**。其中三条要按契约写成机器可读的键（`composite`／`personWindow`／`captionSafe`，放在一个带 `composite` 键的 fenced `json` 代码块里）；键名与取值域以 `video-craft` 的 `references/composition-facts-contract.md` 为准，本 Skill 不自己造字段名。四条各写什么见 `03_video_route.md` 的 V1。

**判断标准**：任意两页并排像一套；任意一页单看能认出是哪一套。**设计判断的框架在 `style_system.md`，这里不重复。**

## 制作

1. 明确这页的信息关系（并列／比较／因果／层级／时序／构成）与第一眼落点，再决定形式。形式要匹配信息形状；不要求逐页填多组同义设计理由。
2. 写 `_internal/02_svg_source/<page_key>.svg`。画幅用开局确认的那一个（`scripts/canvas_frame.py` 是唯一取值处），同一套保持一致。图形和文字保留 SVG 原生对象。
3. 纵向位置从 `design_direction.md` 里的步长导出；页眉、页脚、页码、栏目名这些跨页锚点，各页用同一组坐标。
4. 真实图片用项目内相对 href，给可修改图片设置稳定 `data-asset-key`。完整显示用 meet，填充用 slice；主体与截图关键信息不能因裁剪丢失。脚本从实际 SVG 提取图片供用户调整，无需 wireframe slot。
5. **给可能被强调的元素铸稳定 `id`**（视频画面路线，交接要求见 `03_video_route.md` 最后一节）。**id 在全片唯一**：把 `page_key` 放进名字里（`beat-04-caption-1`），因为各屏会被内联进同一个 DOM，重复的 `id` 会让按 id 指名只命中第一屏。名字还要能读出它在画面里是什么。**用 id，不用 DOM 序号**——重渲时只要多出一个 `<text>`，按序号指的元素就会静默绑到别的东西上。同一页里 id 重复是非法 HTML，检查画面会拦下。
6. 幻灯片出口的严格模板：先调用 `apply_fidelity_template.py` 实例化选中的空内容 canvas，再填入内容层，保留指定品牌锁层。自主设计与视频画面路线都不需要 fidelity 包。

密度、字号档位、配色、是否用容器，都是设计决定，**没有脚本阈值**。页面声明的 `mode` 只在**幻灯片出口**上带一条硬约束：`讲` 页的字号不得低于 18px，`读` 页不得低于 12px。视频出口的字号可读性由你看渲染图判断。

## 看图与修复

通常做约 3 页就运行：

```bash
python scripts/orchestrate/ppt_pipeline.py <project> check --pages opening evidence recommendation
```

页数可按复杂度调整。**`check` 是「渲染 + 机器测量」**：渲染当前 PNG，跑技术检查，并带回一组只读测量。技术检查只留两类：**在任何风格下都是缺陷**的（文字压文字、**元素出画布含文字**、空页、图片被拉伸），和**幻灯片出口**的「转成 PPT 会坏」那一组。它不对密度、字号档位、构件选择、留白多少发表意见——那些判断归你。被跳过的检查会在输出里说明为什么跳过。

这条技术检查和「转换 PPT」**共用同一套坐标几何**：校验器直接调用转换器的坐标模型，不自己再算一份（两份曾经分歧到同一份输入差 100px）。**幻灯片出口的权威运行点在导出时**——`export` 会先逐页跑一遍，有错误就拦下不转换；`check` 里那次是提前预警。**视频画面路线没有导出这一步，`check` 就是权威运行点。**

所以 `check` 干净不能代替看图。**实际查看每页 PNG 大图**——不是联系表里的缩略格——核对阅读层级、截断、重叠、图表标签、图片主体和来源；再看整套 contact sheet 检查构图重复与节奏。**执行这一步的模型必须能读图**；当前模型看不了就把它派给能看的模型。不能只看 SVG 代码宣称视觉通过。

看到启发式提示（`OUTSIDE_SAFE_MARGIN` 这类 info 级提示）结合 PNG 判断；不必为消除提示而改设计。

修订后重新 check；有进展就继续，不限制只修一次。同一问题无进展时改变表达或实现方法；工具权限失败走对应权限恢复，不将失败包装成“无视觉能力但通过”。

看过当前图片后，用 check 返回的 render_token 记录具体观察：

```bash
python scripts/orchestrate/ppt_pipeline.py <project> inspect --page opening --render-token <token> \
  --position 'x=180,y=240,w=864,h=90' \
  --clean \
  --note '标题与证据均可读，截图关键信息完整；已修复来源与正文的重叠' \
  --first-glance '左侧 48px 主标题' \
  --design-check '规则4 重心唯一；规则10 底部空档不承载分组，属空隙，已收紧；无其他违规'
```

**四件都要给**：`--position` 指出当前 PNG 上的一处具体位置（必须落在画布内）；`--clean`（看过、无缺陷）与 `--must-fix`（看过、有缺陷且已记录）**二选一**；`--note`、`--first-glance`、`--design-check` 照旧。填 `ok`／`👀` 不通过。这条记录不证明模型真的看过图，也不代表人审通过——但**「这一屏第一眼落在哪、缺陷在哪一处」是它能被证伪的地方**。

## 收尾：按 `style_system.md` 的规则自检

`check` 每页会带回一组**只读测量**——字号档位、最大／最小尺度比、等面积容器组、内容底部到页脚线的空档、与其他页共用的基线。**它们是事实不是判定**，但对着数字走一遍 `style_system.md` 的完成前自检，比凭印象可靠：等面积容器组多半就是「等权没有重心」，尺度比很小而档位很多就是「层级失效」，底部空档先问它有没有承载分组。

结论必须落到 `inspect` 的字段上（`--first-glance` 与 `--design-check`，都必填）：**第一眼是什么**、**对照了哪几条规则、有没有违规**。空着不通过——这一步以前只收自由文本，所以可以被跳过，而它实际上被跳过了。

**这一路自检的判据是「这个 PPT 做得好不好」**：重心、层级、节奏、可读性。**模板审阅的自检判据不同**——它问的是「有没有提炼出足够的模板规律」（`01_template_intake.md` 第 6 步、`template/template_visual_gate.py`），两者不要套用同一句结论。

自检不等于人审。自检通过只说明你按规则看过并留下了结论，不构成用户批准。

## 用户返修

读取 `_internal/05_review/feedback.json` 的全部 items。区域标注、整页重排、文案与图片修改都回到本阶段。逐项落实后用 `resolve --feedback-id <id> --note <实际处理>` 记录；脚本要求受影响内容发生改变，但语义是否兑现仍要对照反馈。新增图片需创建实际区域并重排，裁剪预览不是已修改的页面。

**用户批「某种形式丑」时，先分清是构件本身，还是执行质量。** 大框小字、低对比容器、内容撑不起容器，都会让一个本身成立的构件显得难看；直接删掉构件可能让整套更单调。用 `resolve` 的说明写清你判断成了哪一种。

## 完成

所有页面技术错误解决，当前 PNG 已查看，整套节奏已检查，无未处理反馈或 must_fix，然后分路：

- **幻灯片路线**：随后进入整套审阅。审阅可选；导出会跑检查画面，并在没审过时提醒一次。
- **视频画面路线**：**审阅是门**。跑 `ppt_pipeline.py <project> review` 让作者逐页过目，意见逐项 `resolve`；作者明确说可以录了，这条路线才算完（`03_video_route.md`）。
